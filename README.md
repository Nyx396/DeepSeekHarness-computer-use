# DSH Desktop Control · 桌面操作

Windows 桌面操作插件测试版，包名 `dsh-desktop-control`，版本 `0.2.5`。面向 DSH Desktop `0.2.1-rc.2`、Windows x64、系统 Windows PowerShell 5.1。使用已有 `dsh-plugin-hub 1.0.0` 的扩展口袋和插件配置页。

## 使用

安装后重新启动 DSH。在扩展口袋中选择“桌面操作”打开插件配置，再进入“桌面操作”；也可从“设置 → 插件配置 → 桌面操作”进入。页面可查看状态、暂停工具和调整截图宽度。

聊天示例：

> 授权本任务使用 computer use。找到我指定的测试窗口，先观察界面，再在输入框中输入“你好，桌面操作”，检查输入结果。

**调用前提：有显著质量收益、明显减轻工作或任务必要性。普通权限还须明确授权当前任务；完全访问模式允许直接开始符合条件的任务，免首次审批。** 能用专用 API、文件或命令行工具充分完成的任务优先使用这些工具，不因技能存在而自动加载、列窗口或截图。同一任务可连续操作，范围变化需新令牌；减少无目的重复截图和自检。

普通权限中的明确授权，指用户提出使用 computer use、桌面控制、接管鼠标键盘，或同意模型此前的申请。只描述“在窗口中输入并点击按钮”这一目标时应先询问，不能自行推断已获授权；宿主完全访问预设适用上述首次免审例外。

用户明确指定 computer use 操作方法或验收桌面交互时，该方法本身属于验收条件。指定步骤应实际使用 `desktop_*` 工具，不能只加载技能，再用命令启动、直接改文件或其他自动化替代。例如打开并输入的桌面测试，应通过观察后的 UI 操作打开文件，再点击编辑区、复核焦点并输入。普通结果型任务仍保持上述低调用优先级。文本输入使用剪贴板粘贴，不要求每次移动鼠标；报告须区分打开、点击、输入和验证各自采用的方法。

`desktop_begin_task` 记录完整任务与具体收益，不启动桌面引擎。通常使用 `scope:"task"`，一次批准覆盖同一任务的窗口枚举、桌面、应用/文件/对话框切换、输入及最终验证，不按窗口拆分审批。仅在用户明确限制窗口时使用 `scope:"windows"` 和完整标题列表；该模式下空列表仍仅允许枚举。普通权限使用 **DSH 原生批准卡片**；后端确认为用户选择的 `danger-full-access` 预设时，免首次审批并签发限定会话和本次任务/明确窗口范围的随机 authorizationId。Auto/自定义模式、模型参数或“已获授权”的自述不能启用该例外。其他 9 个桌面工具始终校验令牌；缺失、伪造、过期或跨会话均拒绝。严格窗口范围按标题过滤枚举；任务范围可发现新窗口，实际观察/输入仍绑定 HWND 和 PID，句柄被另一进程复用时拒绝。任务相关性由模型遵守，后端不能仅凭窗口标题自动判断；跨任务必须重新授权。离开完全访问模式会使通过该例外签发的令牌失效。

完整任务结束调用 `desktop_end_task` 撤销令牌并释放引擎，不在发现窗口或切换应用时结束。相同任务与范围的重复 begin 会返回尚有效的原令牌，无需重复审批；同一未结束任务可跨轮次继续。暂停、重启或空闲 30 分钟会撤销授权。只想枚举时可用 `scope:"windows"` 和空窗口列表，这不允许观察窗口内容或输入；`scope:"task"` 的空标题列表则表示不按标题限制当前任务。任务含义和是否满足收益条件仍由模型及用户判断；后端不理解语义，用户应在批准卡片中核对范围，完成后结束任务。批准只保存在内存，不持久化为长期许可。

Windows 短暂占用状态文件时，插件仅对原子替换写入做有界重试（最多额外等待约 385 毫秒），不删除旧状态文件，不重放任何桌面输入。持续失败仍返回原始错误。

插件给当前模型注册 11 个工具：任务批准与结束工具 `desktop_begin_task`、`desktop_end_task`，以及 `desktop_health`、`desktop_windows`、`desktop_activate`、`desktop_observe`、`desktop_click`、`desktop_type_text`、`desktop_keypress`、`desktop_scroll`、`desktop_drag`。观察支持截图、UI Automation 和系统 OCR。截图作为 DSH 原生图片附件交给当前会话模型，模型须声明图片输入能力。

支持图片的自定义模型还须在 DSH 供应商模型配置中声明 `input: [text, image]`；以实际供应商能力为准，插件不根据名称猜测。若截图因模型声明缺失而失败，UIA 树回退可以完成桌面操作，但不能视为视觉验收通过，应明确报告该限制。

插件同时注册独立可加载的 **computer use** 技能，技术名为 `computer-use`。模型可以调用 `skill({"name":"computer-use"})`，用户也可在技能菜单中调用。技能目录随插件安装、注册和卸载，不修改用户的全局技能目录；它仍使用上述工具执行操作，并非第二套桌面引擎。

截图结果含 `imagePreviews[].markdown`，模型应原样用于最终回复，不再猜测附件库内部路径。预览 PNG 位于 `<DSH_HOME>/cache/dsh-desktop-control/previews`，按内容去重。清理该缓存会使旧回复中的文件预览失效；DSH 原生工具附件仍由宿主保留。预览生成失败会明确返回错误，不掩盖为“全程无报错”。

不需要本地大模型、独立视觉模型、Python、uv 或另一个 API Key。截图和界面文字会经现有 DSH 模型路由发往当前供应商，本地只负责观察与执行。

目前会短暂占用真实鼠标、键盘与焦点。**Esc 或 Ctrl+Alt+F12 停止后，立即撤销旧令牌与观察凭据，并保持停止，包括完全访问模式。** 模型不得自行重新启用技能、重试或刷 health。用户要求继续时，调用一次 `desktop_begin_task`，在 DSH 原生“恢复桌面控制”确认卡片中选择恢复，后端才刷新令牌及底层恢复标记；可以在同一轮立即继续，无需等待或重启。此确认使用用户交互通道，不受完全访问的普通审批 `never` 策略阻断，也不修改全局权限模式。取消、关闭、请求中断或确认通道不可用均保持停止。换轮次、等待、切权限模式及重启插件不能自行解除停止；恢复后必须重新观察，禁止重放旧输入。

停止闩锁存于 `<DSH_HOME>/dsh-desktop-control-stop.json`，任务令牌仍只保存在内存。配置页的暂停会取消调用并撤销令牌，重新启用开关不会绕过 Esc 后的人工恢复确认。

恢复确认在工作台输入区呈现紧凑卡片，复用原生待交互通道，仅有“保持停止”和“恢复任务”两个固定按钮，不提供自由回答或第三种决策。任务及窗口范围可展开核对。只替换本插件的恢复确认，其他问答与审批界面不变；后端拒绝自由文本、混合选项或缺失结果。

每次输入必须携带最新 observationId，单次使用、120 秒有效、绑定当前会话/轮次/窗口。窗口位置或进程变化会拒绝输入。同一时刻由一个会话持有桌面，轮次结束释放，空闲超过 30 秒释放。坐标使用窗口内 0–1000 比例，适应多屏负坐标及图片重编码；每次输入后仍须重新观察验证。

所有目标使用统一前置流程：观察前自动还原、置前目标；仍有遮挡时，最小化系统确认位于目标上方且与其重叠的普通窗口，再重新观察。`desktop_activate` 也使用同一流程，无需模型逐一寻找最小化按钮。`targetPreparation` 返回准备状态、布局变化及被收起窗口的原状态。不关闭程序、不越过模态对话框；任务结束不全局还原窗口覆盖结果。自动最小化不授予读取或操作遮挡窗口内容的权限。

输入前再次校验目标准备情况，并在原生派发前检查焦点、坐标实际命中的窗口及共享鼠标位置。如果中途窗口布局变化，先准备目标，再返回 `DESKTOP_REOBSERVE_REQUIRED`，模型沿用原任务令牌、重新观察后继续。本次不会派发旧输入。遮挡消失后的前台切换会在同一次准备中有界等待重试；焦点仍未就绪且遮挡列表为空时返回 `DESKTOP_TARGET_FOCUS_NOT_READY` 与前台窗口元数据，不误报为透明层遮挡。透明鼠标穿透不等于允许向非目标焦点窗口输入。仍无法准备时返回具体原因；截图能看到后台内容不等于该位置可点击。Esc 和暂停同样中止准备流程。

## 0.2.5 焦点恢复

0.2.5 将透明桌宠及分层浮层下的焦点恢复纳入统一准备流程。激活目标时连接前台与目标线程的输入队列，针对透明/分层浮层及任务栏过渡增加最多 1600 毫秒的轮询恢复窗口；只在确实取得目标前台后才允许输入。不修改桌宠样式，不按进程名放行，也不改变输入命中和停止规则。诊断中的 `focusRecoveryRevision: 1`、`focusAttempts`、`focusWaitMs`、`foregroundSamples` 和窗口扩展样式可供排查。

准备阶段确认未派发输入的焦点失败返回结构化 `ok:false`、`inputDispatched:false` 和 `recovery.requiresSkillReload:false`，保留引擎与当前任务授权，清除旧观察凭据；它不是成功截图，也不能用于输入。模型可沿用令牌显式激活目标一次，再重新观察；仍失败应报告前台窗口并暂停该目标。超时、取消、Esc、真正遮挡和结果未知的输入错误仍保持原处理。

本版已通过针对性自动化回归和透明桌宠保持开启的桌面打开文件、编辑器输入及截图验证。明确准备失败的错误恢复分支由自动化测试覆盖，不保证所有浮层、权限和安全软件环境均可操作。安全软件保护的浏览器和开始菜单发现问题不属于本次修复范围。

若桌面准备后前台仍停留在任务栏（`Shell_TrayWnd`）或其他窗口，可在同一任务令牌下显式调用一次 `desktop_activate`，再重新观察后继续；不重放旧输入。若仍未就绪，停止并报告实际前台窗口，避免反复激活。系统持续拒绝焦点切换时，本版仍会拒绝输入。

## 安装

ZIP 解压后，先运行“检查环境.cmd”，再运行“安装.cmd”；卸载使用“卸载.cmd”。必须完整解压，保留 `plugin/` 和 `tools/`。需要先安装 `dsh-plugin-hub 1.0.0`。ZIP 不包含本机验证记录、测试任务、截图、日志或 DSH 运行时副本。

先完全退出 DSH（包括托盘）。安装器不主动结束用户进程。源码目录也可直接运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\portable.ps1 -Mode Check
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\portable.ps1 -Mode Install
# 卸载：
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\portable.ps1 -Mode Uninstall
```

可选参数：`-DshPath <安装目录>`、`-DshHome <DSH 数据目录>`、`-Profile desktop`。明确不保留旧插件本体时可传 `-SkipPluginBackup`；仍保留 profile 元数据，失败时移除无法恢复的插件注册，避免悬空引用，再从源码或 ZIP 重装。默认安装仍备份插件本体，此选项只影响本次调用。

安装器将文件夹复制到 `<DSH_HOME>/custom-plugins/dsh-desktop-control/<profile>`，通过 DSH 自带 CLI 以 `link:` 注册。使用前会检查宿主/插件中心版本；离线执行且忽略安装脚本；备份 profile 元数据和旧插件，失败自动回滚。备份位于 `<DSH_HOME>/backups/dsh-desktop-control/`。运行不依赖解压前的源码目录。

设置存于 `<DSH_HOME>/dsh-desktop-control.json`。引擎在首次工具调用时启动，空闲时不截图或操作鼠标；配置页暂停会关闭引擎。临时文件位于独立临时子目录；卸载插件上下文时关闭进程并清理。异常退出可能留有临时截图，后续版本再补启动清理。安装器只检查、复制运行文件，忽略开发测试目录。

## 开发和维护

运行时没有外部 npm 依赖；源码直接可用。

```powershell
node --test test/*.test.mjs
npm run test:focus
```

这些命令用于包含 `test/` 的维护源码。C# 回归采用模拟窗口管理器，不创建真实窗口或发送输入。真实桌面验收需在 DSH 内通过 desktop 工具执行，记录实际焦点和最终结果；不能用模拟测试代替。

目录：`lib/` 为 DSH 接入与控制；`vendor/windows-engine/` 为固定版本的 MIT 引擎；`skills/` 为模型操作流程参考。维护源码另有 `test/` 和打包工具；公开的 `release/code` 与 ZIP 仅含运行代码、必要说明、安装器及许可证，不含开发测试、调查、日志或本机配置。

在维护源码运行 `npm run package`，依据自动化与实机验收记录生成 `release/dsh-desktop-control-0.2.5-win-x64.zip`、整包 SHA-256 及 `release/code`。固定文件清单不包含测试输出或本机记录。`release/code` 将 package.json 放在根目录，并附带可直接使用的安装 CMD 和 `tools/portable.ps1`；ZIP 使用 `plugin/` 加顶层安装器的布局。两者的运行文件一致，公开 package.json 不保留未分发的开发脚本。

`lib/windows/visuals.cs` 是自有视觉层，`lib/windows/target.cs` 与 `target.ps1` 实现窗口准备和输入命中检查。启动已批准的桌面引擎时，在本实例临时目录组合视觉与目标适配；上游停止钩子及分发的 vendor 原始文件保持原字节。`lib/target.js` 为固定上游的原生输入入口注入检查，结构不匹配时拒绝运行。

上游来源、许可证和版本锁见 [THIRD_PARTY.md](THIRD_PARTY.md)。更新时按 `UPSTREAM.json` 固定新提交，检查原始文件差异，重跑坐标、取消、互斥、宿主与原生窗口测试后再更改版本。不要直接追随 main 自动更新。

## 初版边界

目标须存在于当前可交互桌面，支持将已最小化的目标还原；不提供虚拟鼠标或并行后台桌面。目标截图失败或只能得到可能被其他窗口遮挡的屏幕裁剪时，会拒绝转发该画面。权限高于 DSH 的窗口、UAC、安全桌面、锁屏和特殊自绘应用可能无法操作。不能最小化的遮挡窗口、模态对话框或无法取得前台权限时会拒绝输入。原生树可能不完整，OCR 只有已安装的识别语言。剪贴板输入支持中文并尝试恢复原内容；操作期间不要同时修改剪贴板。

原生批准与后端任务令牌用于限制模型自行推断授权。任务批准后的执行仍依赖模型对画面与目标的理解。旧式非 DPI 感知应用的 PrintWindow 图像可能存在缩放差异，不能仅凭首次坐标派发宣称成功。

这是桌面级能力，不受文件工作区边界限制；安装和停用由用户控制。模型的外部动作审批仍由 DSH/用户策略负责。初版不含应用白名单、任务回放、跨进程桌面锁或无人值守保证。
